Endpoints

Reports

Candidate reports for hiring managers.

A report is the write-up of a candidate for a hiring manager. Reports never change once written, so they cache well.

List an opportunity’s reports

Section titled “List an opportunity’s reports”
GET/api/v1/opportunities/{id}/reportsread

Newest first, without the report bodies. Not paged.

Get a report

Section titled “Get a report”
GET/api/v1/reports/{id}read
Field Description
call_id The call the report was built from, or null when it was built from the opportunity’s material without a call.
style brief, executive or full.
assessment The recruiter’s verdict: strong, possible or gaps. null if not set.
ai_assessment The AI’s verdict, with the same values.
html_url, text_url Paths to the report body. Add them to your Paladin address.

Get a report as HTML

Section titled “Get a report as HTML”
GET/api/v1/reports/{id}/htmlread

A complete HTML document with its own styles, and no scripts or outside resources. To show it on your own page, put it in a sandboxed iframe so its styles don’t mix with yours:

Get a report as text

Section titled “Get a report as text”
GET/api/v1/reports/{id}/textread

The same report as plain text, one line per paragraph or list item. Use it for search, or to give to an AI model.

All three report routes send an ETag and can be cached for a day.
